# incus-cluster — three Incus members, one bootstrap

A 3-member Incus cluster. `node-1` bootstraps the cluster database; `node-2` and
`node-3` are **data-only** members — their node files contain nothing but an
address, and they still end up as full cluster members.

Generated by:

```bash
nix flake init --template github:kitsunoff/nixcluster#incus-cluster
```

## Layout

```text
flake.nix                          flake-parts + import-tree + nixcluster
modules/
  base.nix                         the NixOS base every member inherits
  clusters/incus-cluster.nix       cluster options (clustering, storage backend)
  nodes/node-1.nix                 bootstrap member
  nodes/node-{2,3}.nix             data-only members (address only)
```

## Why data-only members matter

Clustering is a **cluster-level** toggle, not a per-member one: `incus.cluster.enable`
applies Incus and the clustering configuration to every member. A member that only
carries `install.ip` therefore still joins.

That is the case worth protecting. When node files are generated — by an operator
that discovered a machine and knows only its address — nobody is around to add a
per-member `incus.enable`. If clustering depended on that patch, generated members
would silently never join.

## Converge order

```text
member-node-1 ──┬──> member-node-2 ──┐
                └──> member-node-3 ──┴──> incus.cluster-join
                                          incus.reconcile
```

- `node-1` installs first: nothing can join a cluster that does not exist yet.
- `node-2` and `node-3` depend on the bootstrap and not on each other.
- `incus.cluster-join` mints a single-use token per joiner and runs
  `incus admin init --preseed` on it. It is idempotent: a member already in
  `incus cluster list` is skipped and says so.

Check it without installing anything:

```bash
nix eval .#clusterConfigurations.incus-cluster.convergeOrder
nix run .#cluster-incus-cluster -- converge --dry-run
```

## What to change

| Where | Field | Why |
| --- | --- | --- |
| `modules/nodes/*.nix` | `install.ip` | the address converge connects to |
| `modules/nodes/node-1.nix` | `install.disk` | the disk the installer wipes — check it |
| `modules/clusters/incus-cluster.nix` | `incus.cluster.storageBackend` | `dir` needs no spare device; use `zfs`/`btrfs`/`lvm` in production |
| `modules/clusters/incus-cluster.nix` | `incus.cluster.bootstrapMember` | pin the bootstrap instead of taking the first name |
| `modules/base.nix` | `users.users.root.openssh.authorizedKeys.keys` | the key converge authenticates with |
| `modules/base.nix` | `boot.loader.grub.device`, `fileSystems."/"` | must match the real disk |
| `modules/base.nix` | `nixpkgs.hostPlatform` | `x86_64-linux` for x86 nodes |

> [!IMPORTANT]
> Keep the member count **odd** (3, 5, …). Incus uses a Raft database: three
> members tolerate one failure, four still tolerate only one.

> [!WARNING]
> First-time installation runs `nixos-anywhere`, which **wipes the target disk**.
> Verify every `install.ip` and `install.disk` before converging.

## Use it

```bash
nix run .#cluster-incus-cluster -- converge --dry-run
nix run .#cluster-incus-cluster -- converge
nix run .#cluster-incus-cluster -- incus list
```

After a successful converge, `incus cluster list` on the bootstrap shows all three
members ONLINE.
