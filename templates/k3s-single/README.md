# k3s-single — one k3s server

The smallest working cluster: a single `k3s.role = "server"` member. Use it to
smoke-test the k3s module, or as the starting point for a cluster you will grow.

Generated by:

```bash
nix flake init --template github:kitsunoff/nixcluster#k3s-single
```

## Layout

```text
flake.nix                          flake-parts + import-tree + nixcluster
modules/
  base.nix                         the NixOS base every member inherits
  clusters/k3s-single.nix          cluster options (which modules, which base)
  nodes/server-1.nix               one file per member
```

## What to change

| Where | Field | Why |
| --- | --- | --- |
| `modules/nodes/server-1.nix` | `install.ip` | the address converge connects to |
| `modules/nodes/server-1.nix` | `install.disk` | the disk the installer wipes — check it |
| `modules/base.nix` | `users.users.root.openssh.authorizedKeys.keys` | the key converge authenticates with |
| `modules/base.nix` | `boot.loader.grub.device`, `fileSystems."/"` | must match the real disk |
| `modules/base.nix` | `nixpkgs.hostPlatform` | `x86_64-linux` for an x86 node |
| `modules/clusters/k3s-single.nix` | the cluster name `k3s-single` | names the CLI app and the NixOS configurations |

> [!WARNING]
> First-time installation runs `nixos-anywhere`, which **wipes the target disk**.
> Verify `install.ip` and `install.disk` before converging.

## Use it

```bash
# What converge would do, in dependency order, without touching anything:
nix run .#cluster-k3s-single -- converge --dry-run

# Install/switch the member, then fetch the kubeconfig:
nix run .#cluster-k3s-single -- converge

# Per-node operations:
nix run .#cluster-k3s-single -- apply server-1
nix run .#cluster-k3s-single -- k3s nodes
```

## Converge order

```text
member-server-1        →  k3s.bootstrap
                          k3s.kubeconfig
```

With one server there is nothing to order; the interesting contract lives in the
`k3s-ha` template.
